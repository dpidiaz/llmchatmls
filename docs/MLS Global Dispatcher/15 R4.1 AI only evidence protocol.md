# MLS R4.1 · Política AI-only para certificación académica

**Decisión editorial (29 de septiembre de 2026):** la revisión humana deja de ser una dependencia, incluida la publicación y los lotes siguientes. No se contratarán revisores ni se prepararán integraciones con APIs pagadas. SOLO CHAT y FREE ONLY. Una auditoría asistida por IA debe identificarse honestamente como tal: **`VERIFIED` es evidencia automatizada y trazable, nunca una aprobación humana `REVIEWED`.**

## Puertas académicas, en orden

1. Confirmar la identidad del artículo canónico: código, versión, SHA-256 del Markdown y enlace a la entrada. No reescribir registros históricos.
2. Crear afirmaciones sustanciales para cada sección explicativa; enlazarlas a fuentes de autoridad A/B con `sourceId`, tipo de respaldo y localizador comprobable. La forma del locator se valida automáticamente; su veracidad **no se deduce de que exista**.
3. Ejecutar una segunda lectura orientada a pasajes de fuentes primarias separada de la generación inicial. Documentar para cada claim: afirmación, fuente, sección, decisión, matices, contradicciones y limitaciones. Prohibido inventar DOI, ediciones, páginas o citas.
4. Validar con las reglas canónicas R33 (identidades, Snapshot, Source Registry, conflicto, estado, provenance) y R4.1 (cobertura y localizadores). Una contradicción o fuente insuficiente obliga a `NEEDS_CORRECTION`, no a `VERIFIED`.
5. Vincular el informe AI, resultado CI, códigos, cantidad de claims, SHA del staging revisado y cualquier limitación en `replacementApproval` bajo protocolo `MLS_R41_AI_EVIDENCE_V1`. Marcar expresamente `generatedWithAI:true`, `humanReviewed:false`, `reviewerType:"ai"`. No crear ni suplantar una firma.
6. Desbloquear el quality hold **únicamente mediante PR con pruebas**, conservando commit histórico y preferencia exclusiva por v3. El Scheduler verifica en vivo que el ref v3 permanece inalterado y que su GitHub Action fijada terminó SUCCESS sobre el mismo SHA antes de permitir Gate 25.
7. Gate 50 y Gate 100 siguen restringidos: no se derivan de aprobar Gate 25 automáticamente. Cloudflare continúa siendo una operación separada.

## Estados honestos

| Código de control | Significado |
| --- | --- |
| `PENDING_CANONICAL_R33_VALIDATION` | No se ha certificado el contenido. |
| `VERIFIED` | R33 + trazabilidad + segunda verificación AI y evidencia/proveniencia registradas para el alcance de claims indicado. |
| `REVIEWED` | Reservado para revisión humana real, **no requerida** por esta política. |
| `NEEDS_CORRECTION` | Fuente insuficiente, contradicción, pérdida de identidad, cuota agotada o fallo de validación. |
| `CERTIFIED_STAGED` | Validado y conservado en staging, no desplegado automáticamente. |

**Criterio de suficiencia:** verificación reproducible hasta el nivel razonable disponible gratuitamente, con incertidumbres visibles; no declarar certeza absoluta ni fabricar revisores. El proyecto no depende técnicamente ni económicamente de una persona verificadora.
