# MLS R4.1 — Buffered Evidence Farm

Status: experimental branch only. No merge, Cloudflare deployment, or production claim migration.

## Objective

Decouple per-entry R33 evidence production from per-entry GitHub writes. GitHub remains canonical for integrated content. The chat context is not authoritative durable storage.

## Confirmed audit findings

- The scheduler lists open Issues, reconciles closed DONE Issues, and persists its ledger through GET/PATCH/GET operations.
- Worker checkpoint verification reads the branch HEAD and can compare commits before accepting a checkpoint.
- The R33 provider already defines `checkpointSizeMax=1` and excludes terminal and active codes from allocation.
- `scripts/R4-evidence-preflight.cjs` recalculates canonical article, claim, link and Evidence snapshot identities before validation.

## Required safety boundaries

1. Offline buffers only consume already-authorized, exclusive Dispatcher assignment exports; they never invent leases.
2. Each checkpoint has one entry, its exact canonical Evidence path, source snapshot, version and SHA-256.
3. The storage medium must provide durable export/reimport and single-writer exclusion. Separate ChatGPT conversations do not automatically share transactional state.
4. A chat-generated status is untrusted. Invoke the existing R33 `evidence git.js` assessment in a canonical checkout, then revalidate on integration.
5. An exported package is immutable and carries a deterministic hash. Repeated imports of identical content are no-ops; divergent content is a conflict, never an overwrite.
6. Before any grouped commit, compare the current corpus manifest and live dispatcher state, including terminal, recovery, expired leases and overlapping ownership.
7. The synchronizer is single-writer. On secondary rate limit, respect response headers, stop GitHub writes, preserve staging, and do not retry from every chat.
8. A package is not INTEGRATED or DEPLOYED merely because it was exported, assessed or synchronized provisionally.

## Pilot gates

Run 10 representative entries first. Demonstrate crash recovery, orphan detection, idempotence, conflicting content rejection, stale corpus rejection, no false VERIFIED promotion, and read-only synchronization planning. Expand 10 to 25 to 50 only after these gates pass. No destructive changes to the existing R4 Dispatcher during the pilot.

## Compatibility

Existing Issue #1433 and #1458 records are historical recovery inputs, not permission to regenerate or reassign them. Reconcile against the current ledger before reuse. Keep R33 source registry, EvidenceLinks, Provenance and APA 7 intact. Do not introduce OpenAI API, other paid API dependencies, Cloudflare editorial writes or new deployment behavior.
